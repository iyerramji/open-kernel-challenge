# Constraints, provenance and unknowns

Sources fetched 2026-10-29: [llms.txt](https://openkernelchallenge.dev/llms.txt), [rules](https://openkernelchallenge.dev/rules), [problem API](https://openkernelchallenge.dev/api/v1/problems/muse_bf16_proj), [serving API](https://openkernelchallenge.dev/api/v1/serving), [terms PDF](https://openkernelchallenge.dev/terms.pdf), [NVIDIA H200](https://www.nvidia.com/en-us/data-center/h200/). Raw snapshots and SHA256 manifest are under `official/`. Refresh before entry.

Hardware: official instructions specify **one H200 SXM for kernels**, **8×H200 for serving**. NVIDIA specifies Hopper, 141 GB HBM3e, 4.8 TB/s, up to 700 W SXM and 900 GB/s NVLink. NVIDIA's BF16 table lists 1,979 TFLOP/s **with sparsity**; the official problem assumes about 989 TFLOP/s dense. Dense projection rooflines must not use the sparse figure. H200 is not Blackwell; NVFP4 storage does not imply native Blackwell FP4 instructions. H200 serving uses Marlin. H100 tuning is architectural guidance and needs H200 remeasurement.

Unknown: clocks/power configuration, host CPU, driver, exact installed package patch versions in the pinned image, actual sustained bandwidth, MIG/sharing configuration and run variance. We did not pull/run the image. Record nvidia-smi, device capability/SM count and package versions in a permitted runtime. This Mac has no CUDA H200; CPU PyTorch is only local validation.

Deadline discrepancy: live API/llms say kernels close Nov 4 2026 11:59 p.m. Pacific; serving opens Nov 5 noon Pacific and closes Nov 19 11:59 p.m. Pacific. API closing instants are Nov 5 00:00 -08:00 and Nov 20 00:00 -08:00. **Terms PDF §3 says contest ends Nov 18 at 11:59 p.m. Pacific; §5 says its rules control conflicting materials.** This is unresolved. Preserve the earlier date for planning and review current materials before participating. No organizer was contacted.

Kernel: one Python file; prepare(weights) once untimed up to 300 seconds; kernel_fn(data,state) timed. Run limit 10 minutes including compilation. No network or extra installs in judge. Image includes torch, Triton, FlashInfer, DeepGEMM, TileLang, CuTe DSL and CUTLASS. Timed calls must be CUDA-graph capturable; no host syncs or input-value-dependent allocation/control flow. Fixed shape/config branches are permitted. No caching/replaying input-derived outputs or moving timed computation into prepare.

BF16 weights/activations remain BF16; router may use BF16 hi+lo with FP32 accumulation. Return BF16 except FP32 router. Relative L2 bound 1e-2, router 1e-4; per-row bound 5×; probe rows 1e-3; finite outputs required. Exact reference/checks are preserved. Nearby shapes and fresh random input matter; scored values may not be hardcoded into results or computation.

Official timing alternates CUDA graph replays against baseline on fresh inputs after cold-L2 flush; median paired ratios, order swaps, fixed replay-cost subtraction (~4 μs), 95% interval at least ±1.5%. Score is geometric mean over six loads of weighted baseline/candidate load times (each shape weight 62). Our local diagnostic timer does not reproduce the private evaluator. TASK “floor” values are theoretical, not measured baseline timings.

Snapshot quotas: 10 scored + 20 check runs per problem/day; serving 1 scored + 3 checks/day, reset 00:00 UTC. Check uses quota. Kernel boards have no prizes; top 50 overall receive serving priority. All board positions provisional until final screening/held-out reruns. Saved leaderboard does not imply any cloned reference or local candidate achieved those scores.

Serving: diff against a55ab7d5ae1bba59ac351e55026fe7f7644ecc5f, source/JSON only under python/sglang/, excluding srt/model_loader/. ≤720 KiB, added lines ≤400 chars, no renames/mode/binary changes. Prebuilt sgl-kernel is not rebuilt. Preserve 8 of 256 experts, all norms/residuals, 2048 sliding window, BF16 activations, FP8 KV cache, released DFlash weights; return 220 tokens/request. TTFT ≤2× stock is a scoring guardrail. No serving patch was created.

External code: installed libraries are allowed by technical instructions. Terms §13 requires rights to submissions and Apache-2.0 for original contributions, subject to third-party rights. This is not blanket permission to relicense public code. MIT/BSD/Apache files still need notices and file-level review. GPU MODE repositories use June 9 Researcher Reciprocity License; their licenses/readmes were identified and no implementation was reused. Candidate bodies are original torch/Triton implementations; the allowed router representation follows the official Apache-licensed SGLang baseline. No downloaded setup/build scripts were executed. Local AST checks are not an official screening guarantee.
